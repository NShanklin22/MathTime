# MathTime Level Runs, Part 1: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every level an end, exactly as `docs/superpowers/specs/2026-11-01-runs-design.md` §7 step 1 describes (approved by the user 2026-11-01): a run of 20 different facts (§1), "Question N of 20" and a 20-segment bar (§2), the finish screen (§3), hidden timing (§4), and each finished run's record (§5), kept in a queue in the browser. There is no API and no upload yet; the key field of §6 is part 2, and the finish screen leaves room for it.

**Architecture:** The game stays one static page of plain ES modules with no build step.
- Each level lists its facts and its run length (`facts`, `problemsPerRun`). `makeProblem` goes: the game draws a run from the facts.
- `game.js` runs a run. Each problem is drawn evenly from the facts not yet asked. `state.solved` counts the correct answers. The last one returns `'finished'`, and `game.result` holds what the run took. The clock is a parameter, so tests pass their own.
- `record.js` turns a result into the record of §5, and `queue.js` keeps records in `localStorage` and finds the best time.
- `finish.js` words and draws the finish screen.
- `view.js` draws the label and the bar, and `layout.js` puts the bar on whole device pixels. `main.js` keeps the record and shows the finish screen.
- `body.at-finish` switches to the finish screen, as `body.at-select` does to the selector.

**Tech Stack:** HTML, CSS, JavaScript (ES modules). `node:test` for unit tests. `@playwright/test` 1.55.1 and `pngjs` for browser tests (the phone project is a real 2× window, the desktop project 1440×900 at 1×). IBM Plex Mono from Google Fonts.

**Visual reference:** `docs/superpowers/specs/2026-11-01-runs-mockup.html`, built in Task 1. Serve it with `npm start` and open it at `http://127.0.0.1:5480/docs/superpowers/specs/2026-11-01-runs-mockup.html?view=play&filled=7`. Tasks 6 and 7 port its CSS and markup into the game. If the user asks for changes when approving it, fold the same changes into the code of Tasks 6 and 7 before running them.

**Rules that apply throughout:**
- Never show the user a UI state that a separate review agent hasn't rendered and measured (Level 1 spec §8). Task 1 ends with the mockup's review, and Task 8 is the gate for the game.
- Work on a branch, `runs`, in a worktree (superpowers:using-git-worktrees). Don't touch `main` until the user approves after Task 8.
- The working copy uses CRLF line endings. Change files with the Edit tool; a script that replaces "\n" strings silently matches nothing.
- Nothing moves during play except the segment that fills. The equation keeps its size and its alignment: every row of the Level 1 spec §6 still holds, measured on painted ink, not on boxes.
- The design mockups in `docs/` import `src/`. They are records of the approved design and stay as they are; small drift in them is expected. The one exception is in Task 3: the Level 2 play mockup gets the two fields the game now needs, or it would stop drawing at all.
- Each new test must fail before its code exists. That is the "run it, see it fail" step in every task, and it is the proof that the test can bite.

### Task 1: The mockup

The bar and the finish screen are designed here, on the game's own code, and reviewed before any of their code is written (runs spec §2, §3).

The proposal:
- **The bar** sits in its own row between the problem area and the keypad. It is centred over the keys, 16px above them. Held sideways, it sits under the problem area, centred on it, with the keypad's bottom gutter below it. Its 20 segments are 14px wide, 2px apart and 6px tall: 318px in all. Where the bar has less room, they are 12px wide (278px), then 10px (238px). They are always whole pixels, and the bar is put on whole device pixels. An empty segment is `--faint`, the colour of the roadmap's upcoming stages. A filled one is `--good`, the green of a correct answer, and it fills at the correct Enter, with the green. The bar takes its row from the problem area, but at the reference sizes the equation is bound by width (phone) or by its 128px cap (desktop), so it keeps its size. Held sideways, the keypad's band ends where the bar's row starts, so the keypad stays centred on the problem area.
- **"Question N of 20"** keeps the label's size, colour and place, centred on its ink over what you see.
- **The finish screen** uses the selector's column: as wide as the keypad, its first ink 40px below the header. The breadcrumb stays ("Levels › Addition › Level 1") and the hearts go. Each line's box is trimmed to its capitals and baseline, so the gaps run from a baseline to the next capitals. Each line is centred on its ink.
  - "Level 1 complete": 17px, 600, `--ink`.
  - 28px below it, the time: 64px, 500, `--ink`.
  - 24px below that, "New best" in 15px, 600, `--good`, or "Best 1:08.9" in `--muted`.
  - 12px below that, the misses: 15px, 400, `--muted`.
  - 40px below that, two buttons side by side, 56px tall and 8px apart, filling the column. "Again" is filled like the keypad's check key, and "Levels" is outlined like a key. Labels are 17px, 600. Focus is a white 2px ring, 4px out, as on the selector's rows.
  - Part 2 puts the key field between the misses and the buttons.

```html
  import { LEVEL1 } from '/src/level1.js';
  import { fontsReady } from '/src/fonts.js';
  import { createScanner } from '/src/scanner.js';
  import { createLayout } from '/src/layout.js';

  const px = v => onLayoutGrid(v, devicePixelRatio) + 'px';

  const finished = params.get('view') === 'finish';

  // earlier run, slower than the best, and the first run, which has no best
  // to beat and so is a new best too.

    lives: 3, typed: last ? String(a + b) : '', problem: { a, b, answer: a + b },

  const layout = createLayout(dom, scan, LEVEL1.possibleAnswers);
  const view = createView(dom, layout, LEVEL1);
  layout.afterMeasure = () => {
    view.render(state);
    dom.qnum.textContent = `Question ${state.question} of 20`;

  // The run bar on whole device pixels, across and down: centred as laid
  // out, it can start at half a pixel at 1x, which would blur every
  // segment's edges. Its segments are whole pixels wide.
  function placeRun() {
    const first = run.firstElementChild;
    const dpr = devicePixelRatio;
    run.style.translate = '';
    const r = first.getBoundingClientRect();
    run.style.translate = `${px(snap(r.left, dpr) - r.left)} ${px(snap(r.top, dpr) - r.top)}`;
  }

  // Each line's ink centred in the column, and each button's label in its
  // button. A line is centred by its advance, and its side bearings and
  // letter spacing would leave the ink off-centre. Its start goes on a
  // whole device pixel, where it is drawn exactly as scanned (small text is
  // drawn on whole pixels at 1x), so the ink is within half a device pixel
  // of the centre. All the reads happen in one pass, between the writes.
  function centreLines() {
    const dpr = devicePixelRatio;
    const lines = [...finish.querySelectorAll('.line')].filter(line => line.textContent);
    lines.forEach(line => { line.style.translate = ''; });
    const found = lines.map(line => {
      const cs = getComputedStyle(line);
      const fs = parseFloat(cs.fontSize);
      const style = { weight: cs.fontWeight, family: cs.fontFamily, color: cs.color, spacing: (parseFloat(cs.letterSpacing) || 0) / fs };
      return { box: line.getBoundingClientRect(), fs, m: scan(line.textContent, style, fs * dpr) };
    });
    lines.forEach((line, i) => {
      const { box, fs, m } = found[i];
      const start = box.left + box.width / 2 - (m.abr - m.abl) / 2 * fs;   // the start that centres the ink
      line.style.translate = px(snap(start, dpr) - box.left);
    });
  }

  function draw() {
    try {
      layout.layout();
      if (finished) centreLines();
      else placeRun();
    } catch (err) {
      console.error(err);
    }
  }

  if (finished) {
    const f = FINISH[params.get('best')] ?? FINISH.new;
    document.body.classList.add('at-finish');
    $('.done-title').textContent = 'Level 1 complete';
    $('.done-time').textContent = f.time;
    $('.done-best').textContent = f.best;
    $('.done-best').classList.toggle('new', f.isNew);
    $('.done-misses').textContent = f.misses;
    dom.status.textContent = `Level 1 complete. ${f.time}, ${f.isNew ? 'new best' : f.best.toLowerCase()}.`;
  } else {
    if (last) dom.eq.classList.add('correct');
    dom.status.textContent = `Question ${state.question} of 20: ${a} plus ${b}`;
  }

  let queued = false;
  const relayout = () => {
    if (queued) return;
    queued = true;
    requestAnimationFrame(() => { queued = false; draw(); });
  };

  fontsReady().then(() => {
    draw();
    document.documentElement.classList.remove('loading');
    const resized = new ResizeObserver(relayout);
    for (const el of [dom.stage, dom.topBar, finish]) resized.observe(el);
    if (finished) $('.again').focus({ preventScroll: true });
    else dom.ans.focus({ preventScroll: true });
  });
</script>
```

```js
// The rules of play, with no DOM. The view asks it what happened and animates.
//
// `state` is one object, updated in place and never replaced: the view and the
// browser tests hold references to it. `level` is the level being played;
// start() switches it.
//
// A run is the level's `problemsPerRun` problems, each a different one of its
// facts (runs spec §1). Its last correct answer finishes it, and `result`
// then says what it took. A third miss, or start() before the end, leaves it
// unfinished, with no result.
//
// phase: 'playing'  – accepting input
//        'correct'  – answer was right; input locked until next() or start()
//        'out'      – third miss; input locked until restart() or start()
//        'finished' – the run's last answer was right; locked until start()
//
// `solved` counts the run's correct answers, each from the moment it is right.
//
// `now` is the clock, in ms (runs spec §4); tests pass their own. Nothing
// shows it. A problem is drawn exactly when the view shows it, so each is
// timed from then to its correct answer, misses included, and the run from
// its first problem to its last answer, feedback and slides included.
export function createGame(level, rng = Math.random, now = () => performance.now()) {
  let current = level;
  let left = [];            // the level's facts not yet asked in this run, in order
  let asked = [];           // the run's answered problems: { a, b, ms, misses }
  let startedAt = 0;        // when the run's first problem was shown
  let shownAt = 0;          // when the problem on screen was
  let result = null;
  const state = { phase: 'playing', question: 1, solved: 0, lives: 0, typed: '', problem: null };

  // A new problem: one of the facts not yet asked, each equally likely.
  function fresh() {
    const [fact] = left.splice(Math.floor(rng() * left.length), 1);
    state.problem = { ...fact };
    state.lives = current.livesPerProblem;
    state.typed = '';
    state.phase = 'playing';
    shownAt = now();
  }

  // The answer on screen is right: time it, and finish the run on its last.
  function answered() {
    const at = now();
    const { a, b } = state.problem;
    asked.push({ a, b, ms: at - shownAt, misses: current.livesPerProblem - state.lives });
    state.solved += 1;
    if (state.solved < current.problemsPerRun) {
      state.phase = 'correct';
      return 'correct';
    }
    state.phase = 'finished';
    result = {
      level: current.n,
      totalMs: at - startedAt,
      misses: asked.reduce((sum, p) => sum + p.misses, 0),
      problems: asked,
    };
    return 'finished';
  }

  // One key from the keypad or keyboard: a digit, 'Backspace' or 'Enter'.
  // Returns 'typed' | 'ignored' | 'correct' | 'finished' | 'wrong' | 'out'.
  // 'typed' means the answer changed: a digit was added or removed.
  function press(key) {
    if (state.phase !== 'playing') return 'ignored';
    if (/^\d$/.test(key)) {
      if (state.typed.length >= current.maxAnswerLength) return 'ignored';
      state.typed += key;
      return 'typed';
    }
    if (key === 'Backspace') {
      if (!state.typed) return 'ignored';
      state.typed = state.typed.slice(0, -1);
      return 'typed';
    }
    if (key === 'Enter') {
      if (!state.typed) return 'ignored';
      if (Number(state.typed) === state.problem.answer) return answered();
      state.typed = '';
      state.lives -= 1;
      if (state.lives === 0) {
        state.phase = 'out';
        return 'out';
      }
      return 'wrong';
    }
    return 'ignored';
  }

  // Only a correct answer moves on; next() in any other phase does nothing.
  function next() {
    if (state.phase !== 'correct') return;
    state.question += 1;
    fresh();
  }

  // Begin a run of `chosen` (the level being played, by default) at question
  // 1, with full lives and a new problem, whatever the phase. A run in
  // progress is left unfinished.
  function start(chosen = current) {
    current = chosen;
    left = [...current.facts];
    asked = [];
    result = null;
    state.question = 1;
    state.solved = 0;
    fresh();
    startedAt = shownAt;
  }

  function restart() {
    start();
  }

  start(level);
  return { state, press, next, start, restart, get level() { return current; }, get result() { return result; } };
}
```

```js
// A finished run as the record kept for it (runs spec §5): the game's result
```

```js
// Finished runs, kept in this browser (runs spec §6). A run goes in here as
// soon as it finishes. Part 2 sends the queue to the API and takes each run
// out once it is stored; until then every finished run stays here, and the
// best time comes from them.
//
// Storage can be missing, blocked or full (Safari's private mode, cleared
// site data). Then nothing is kept, and the game plays on regardless.
const KEY = 'mathtime.runs';

// The browser's localStorage, or null where even reading it is refused.
function browserStorage() {
  try {
    return globalThis.localStorage ?? null;
  } catch {
    return null;
  }
}

export function createQueue(storage = browserStorage()) {
  // The kept runs, oldest first: [] if there are none or they can't be read.
  function read() {
    try {
      const runs = JSON.parse(storage.getItem(KEY));
      return Array.isArray(runs) ? runs : [];
    } catch {
      return [];
    }
  }

  // Keep `record` after the others. Returns whether it was kept.
  function add(record) {
    try {
      storage.setItem(KEY, JSON.stringify([...read(), record]));
      return true;
    } catch {
      return false;
    }
  }

  // The fastest kept total time of Level `n`, in ms, or null if none is kept.
  function best(n) {
    const times = read().filter(r => r?.level === n && Number.isFinite(r.totalMs)).map(r => r.totalMs);
    return times.length ? Math.min(...times) : null;
  }

  return { add, best };
}
```

```js
import { snap, onLayoutGrid } from './ink.js';

// The finish screen (runs spec §3).

// A time as m:ss.s. Tenths are cut, not rounded, as a stopwatch does: it
// never shows a time that hasn't been reached.
export function formatTime(ms) {
  const tenths = Math.floor(ms / 100);
  const seconds = (tenths % 600) / 10;
  return `${Math.floor(tenths / 600)}:${seconds.toFixed(1).padStart(4, '0')}`;
}

// What the finish screen says for a run of Level `n` that took `totalMs`
// with `misses` misses, against `best`: the fastest earlier run's time, or
// null if there is none. Only a faster run is a new best, not a tie; the
// first run has nothing to beat, so it is one. `said` is what screen
// readers hear.
export function finishText(n, totalMs, misses, best) {
  const time = formatTime(totalMs);
  const isNew = best === null || totalMs < best;
  const was = isNew ? '' : formatTime(best);
  return {
    title: `Level ${n} complete`,
    time,
    best: isNew ? 'New best' : `Best ${was}`,
    isNew,
    misses: misses === 0 ? 'No misses' : misses === 1 ? '1 miss' : `${misses} misses`,
    said: `Level ${n} complete. ${time}, ${isNew ? 'new best' : `best ${was}`}.`,
  };
}

// The screen in `root` (index.html): its lines, and two buttons that call
// again() and levels().
export function createFinish(root, scan, { again, levels }) {
  const $ = sel => root.querySelector(sel);
  const againButton = $('.again');
  againButton.addEventListener('click', again);
  $('.levels').addEventListener('click', levels);

  // The Enter of the last answer may still be held: its key repeat (about
  // 0.5s) would otherwise press "Again" as soon as it has focus.
  root.addEventListener('keydown', e => {
    if (e.repeat && (e.key === 'Enter' || e.key === ' ')) e.preventDefault();
  });

  // Fill in the lines from finishText().
  function show(text) {
    $('.done-title').textContent = text.title;
    $('.done-time').textContent = text.time;
    $('.done-best').textContent = text.best;
    $('.done-best').classList.toggle('new', text.isNew);
    $('.done-misses').textContent = text.misses;
  }

  // "Again" has the focus, so Enter starts a new run.
  const focus = () => againButton.focus({ preventScroll: true });

  // Each line's ink centred in the column, and each button's label in its
  // button. A line is centred by its advance, and its side bearings and
  // letter spacing would leave the ink off-centre. Its start goes on a
  // whole device pixel, where it is drawn exactly as scanned (small text is
  // drawn on whole pixels at 1x), so the ink is within half a device pixel
  // of the centre. All the reads happen in one pass, between the writes.
  // Run it while the screen shows, after every layout.
  function place() {
    const dpr = devicePixelRatio;
    const lines = [...root.querySelectorAll('.line')].filter(line => line.textContent);
    lines.forEach(line => { line.style.translate = ''; });
    const found = lines.map(line => {
      const cs = getComputedStyle(line);
      const fs = parseFloat(cs.fontSize);
      const style = { weight: cs.fontWeight, family: cs.fontFamily, color: cs.color, spacing: (parseFloat(cs.letterSpacing) || 0) / fs };
      return { box: line.getBoundingClientRect(), fs, m: scan(line.textContent, style, fs * dpr) };
    });
    lines.forEach((line, i) => {
      const { box, fs, m } = found[i];
      const start = box.left + box.width / 2 - (m.abr - m.abl) / 2 * fs;   // the start that centres the ink
      line.style.translate = onLayoutGrid(snap(start, dpr) - box.left, dpr) + 'px';
    });
  }

  return { show, focus, place };
}
```

```js
function keepRun() {

  queue.add(record);

  if (result === 'typed') view.renderAnswer(game.state.typed);
  if (result === 'wrong') view.showWrong(game.state);
  if (result === 'correct') view.showCorrect(game.state, () => game.next());

    view.showFinished(game.state).then(shown => { if (shown) toFinish(text); });

}, () => game.state.typed);

// every one loaded since. Their load events need no second measure.
const measuredFaces = new Set();
let measuredOnce = false;

// One bad measurement must never leave the page blank or stop later layouts.
function safeLayout() {
  try {
    layout.layout();
    if (document.body.classList.contains('at-finish')) finish.place();
    if (!measuredOnce) {
      measuredOnce = true;
      for (const face of document.fonts) if (face.status === 'loaded') measuredFaces.add(face);
    }
  } catch (err) {
    console.error(err);
  }
}

let queued = false;
function relayout() {
  if (queued) return;
  queued = true;
  requestAnimationFrame(() => {
    queued = false;
    safeLayout();
  });
}

// Measure from scratch when the ink changes without a resize: a font that
// arrives after fontsReady() gave up, or a new device pixel ratio (moving to
// another screen), which ResizeObserver does not report.

  scan.reset();
  relayout();
}
function onFontsLoaded(e) {
  const fresh = e.fontfaces.filter(face => !measuredFaces.has(face));
  fresh.forEach(face => measuredFaces.add(face));
  if (fresh.length) remeasure();
}
function watchPixelRatio() {
  matchMedia(`(resolution: ${devicePixelRatio}dppx)`).addEventListener('change', () => {
    watchPixelRatio();               // re-arm for the new ratio
    remeasure();
  }, { once: true });
}

  safeLayout();

  // is hidden, so it alone would never report a resize. Fitting the header
  // only changes which crumbs show, not the header's size, so this can't loop.
  const resized = new ResizeObserver(relayout);
  resized.observe(dom.stage);
  resized.observe(dom.topBar);
  document.fonts.addEventListener('loadingdone', onFontsLoaded);
  watchPixelRatio();
});
```
